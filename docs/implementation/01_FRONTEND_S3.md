# 01 Frontend S3

## Goal

Provision the private Amazon S3 bucket that will hold the Next.js static artifact from `out/`.

```text
Terraform
    |
    v
private frontend S3 bucket
```

CloudFront will read this regular S3 bucket through Origin Access Control in [step 04](04_CLOUDFRONT.md). Terraform owns the bucket configuration; GitHub Actions will build and upload `out/` in step 03. Terraform does not upload frontend files.

## Part A - Manual Console Lab

Status: **Completed**.

The console lab created and verified a general purpose S3 bucket with:

- all four S3 Block Public Access settings enabled;
- Object Ownership set to `BucketOwnerEnforced`, with ACLs disabled;
- Versioning enabled;
- default SSE-S3 (`AES256`) encryption;
- a bucket policy denying requests without TLS;
- S3 Static Website Hosting disabled;
- no public ACL or public allow policy;
- an empty, private bucket.

This exercise established the expected AWS configuration. Terraform is now the source of truth. Before the first Terraform apply, delete the manual lab bucket after confirming that it is empty and no longer needed. This prevents a global bucket-name conflict; do not delete a bucket that contains data you need.

## Part B - Terraform Reimplementation

### Structure

```text
terraform/
├── modules/
│   └── application/
│       ├── s3.tf
│       ├── variables.tf
│       └── outputs.tf
└── environments/
    └── dev/
        ├── .terraform.lock.hcl
        ├── versions.tf
        ├── providers.tf
        ├── main.tf
        ├── variables.tf
        ├── terraform.tfvars
        └── outputs.tf
```

`modules/application` contains reusable application infrastructure. `environments/dev` supplies the configuration and local state boundary for the dev environment. `terraform init` generates the committed dependency lockfile; the downloaded `.terraform/` directory remains ignored. Remote state and additional environments are intentionally deferred.

### Local AWS authentication

```text
Developer
    ↓
AWS IAM Identity Center
    ↓
AdministratorAccess permission set
    ↓
AWS CLI profile: aws-learning-dev
    ↓
temporary credentials
    ↓
Terraform
    ↓
AWS API
```

The project does not use IAM User access keys and does not hardcode AWS credentials. The AWS CLI SSO cache supplies temporary credentials through the standard AWS credential chain. When the session expires, authenticate again:

```powershell
aws sso login --profile aws-learning-dev
$env:AWS_PROFILE = "aws-learning-dev"
```

The current AdministratorAccess permission set is for the local learning workflow. The later GitHub deployment path will use OIDC and a purpose-built least-privilege role rather than permanent access keys.

### Commands

Format all Terraform files from the repository root:

```powershell
terraform fmt -recursive terraform
```

Then authenticate, select the profile, and run Terraform from the dev root:

```powershell
aws sso login --profile aws-learning-dev
$env:AWS_PROFILE = "aws-learning-dev"

Set-Location terraform/environments/dev
terraform init
terraform validate
terraform plan
```

Review the plan carefully. To create the bucket yourself after confirming the manual bucket is gone:

```powershell
terraform apply
```

Codex does not run `terraform apply` in this step.

## Terraform-managed configuration

| Console setting | Terraform configuration |
| --- | --- |
| General purpose bucket | `aws_s3_bucket.frontend` |
| Four Block Public Access controls | `aws_s3_bucket_public_access_block.frontend` |
| Bucket owner enforced; ACLs disabled | `aws_s3_bucket_ownership_controls.frontend` |
| Versioning enabled | `aws_s3_bucket_versioning.frontend` |
| SSE-S3 / AES256 | `aws_s3_bucket_server_side_encryption_configuration.frontend` |
| Deny non-TLS requests | `aws_s3_bucket_policy.frontend_tls_only` generated by `aws_iam_policy_document` |
| Static website hosting disabled | No website configuration resource is declared |
| Object Lock disabled | No Object Lock configuration is declared |
| Empty bucket | Terraform does not upload `out/` or any object |

The bucket policy contains only an explicit deny for insecure transport. It grants no principal access and does not make the bucket public. CloudFront access is added later when the OAC and distribution exist.

## Verification after apply

Use Terraform outputs and read-only AWS Console or CLI inspection to confirm:

- [ ] the bucket exists in the intended account and `ap-southeast-1`;
- [ ] all four Block Public Access settings are enabled;
- [ ] Object Ownership is `BucketOwnerEnforced` and ACLs are disabled;
- [ ] Versioning is enabled;
- [ ] default encryption is SSE-S3 (`AES256`);
- [ ] the TLS-only `DenyInsecureTransport` bucket policy exists;
- [ ] S3 Static Website Hosting is disabled;
- [ ] the bucket has no public access;
- [ ] the bucket contains 0 objects.

Versioning retains replaced artifacts and can increase storage cost. A lifecycle policy should be reviewed when deployment history requirements are known. CloudTrail data events, CloudWatch metrics, and delivery/access logging are deliberately deferred to the monitoring step because they can add cost and operational data.
